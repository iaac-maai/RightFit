The second version (11 Nov, `results_2026-11-11.md`) had not yet been scored on the test sets of the first version, because three labels of set A waited for Luca. He answered them on 28 Nov 2026, and the labels in `test_labels.csv` already said what he answered:

No label was changed. The model was scored once, on set A only, with `python -m model.evaluate_pages data/raw/models/page_classifier_v2.joblib A`. Set B was not run and the model was not retrained.

## Set A

The 15 PDFs of the two real packages, P01 and P02: 111 pages, 4 of them scans without text. 81 data sheet pages, 23 declaration pages, 4 certificate pages, 3 other pages, no manual pages.

| Most frequent mistakes (true → guessed) | data sheet → manual 18, declaration → other 8, data sheet → other 8, declaration → manual 2 | data sheet → other 65, declaration → other 16 |

On the same set the first version had 25 % of pages right and the keyword search 27 % (`results_2026-10-29.md`).

## What it says

On the real packages of the first test, the second version gets 68 % of pages right, against 27 % for the keyword search and 25 % for the first version. The gain is on data sheets: it finds 68 % of them, the keywords 20 %. When either method names a declaration, a data sheet or a certificate it is right every time; the misses go to `other` or `manual`. The model's main mistake is taking 18 data sheet pages for manual pages. It still finds only 57 % of the declarations.

## Limits

- Set A is P01 and P02, from the same single project as the second batch the model trained on.
- The labels are Luca's, confirmed on 28 Nov 2026; 111 pages is a small set, and some classes have only 3 or 4 pages.
- 4 pages are scans without text; neither method reads scans yet.
- Each set is scored once per model; this is the only score of version 2 on set A. Set B (manuals with hidden declarations) is still to be scored.
