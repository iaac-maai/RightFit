# Page classifier: second version, 11 Nov 2026

The first version failed on data sheets, because almost none of its training pages looked like the sheets in real packages. This version also trains on the second batch of real packages. The model itself is unchanged.

## Data

- The public manufacturer PDFs of the first version.
- The second batch: 48 real packages from the same project as P01 and P02. Each file takes its type from its own name or from the attachment list of its form, by fixed rules (`model/batch2.py`); no AI labels them. 167 documents could be labelled this way (161 from the name, 6 from the form). The others state no type and stay out.
- Left out: the turned-down revision of P02, and any file identical to one in the first locked test.
- Split by MAF, a quarter of the MAFs of each discipline held back. Revisions of one MAF, and MAFs that share an identical file, stay on one side. Training: 117 documents, 521 pages. Locked test: 50 documents, 184 pages.
- At most 40 pages of one class per document, as before, and scans without text don't train the model. That gives 885 training pages: 277 manual, 257 data sheet, 195 declaration, 103 certificate, 53 other.

File names can carry project names, so the list of files stays on the laptop (`data/raw/models/batch2_files.csv`). Only these counts are in Git.

## Cross-validation on the training documents

Each MAF, or each public document, is left out in turn. The locked test was not used.

| | Our model | Keyword search |
|---|---|---|
| Pages right | 65 % | 35 % |
| Macro F1 | 0.60 | 0.42 |
| Declaration pages found (right when it says so) | 62 % (73 %) | 35 % (84 %) |
| Data sheet pages found | 70 % (66 %) | 19 % (65 %) |
| Certificate pages found | 42 % (77 %) | 63 % (74 %) |
| Manual pages found | 73 % (74 %) | 30 % (94 %) |
| Other pages found | 57 % (26 %) | 89 % (8 %) |

The first version found 6 % of the data sheet pages in cross-validation. This one finds 70 %. The keyword search still finds more certificates, and when it names a declaration or a manual it is right more often.

## Locked test

Run once on 11 Nov 2026, on the 184 locked pages of the second batch, after Luca checked them; he kept every label the rules gave. The two test sets of the first version were not run on this model: Luca has still to answer the three questions on set A from 29 Oct, and a set is scored only once per model.

| | Our model | Keyword search |
|---|---|---|
| Pages right, of 184 | 115 (62 %) | 64 (35 %) |
| Pages right, of the 156 with a text layer | 115 (74 %) | 64 (41 %) |
| Macro F1 | 0.60 | 0.45 |
| Declaration pages found (right when it says so) | 76 % (91 %) | 58 % (85 %) |
| Data sheet pages found | 69 % (78 %) | 9 % (100 %) |
| Certificate pages found | 51 % (100 %) | 89 % (75 %) |
| Manual pages found | 13 % (18 %) | 7 % (100 %) |

On real package pages the model now clearly beats the keyword search, above all on data sheets: it finds 69 % of them, the keywords 9 %. On the real packages of the first test, the first version found 15 %.

The keyword search still finds more certificates. Both fail on manuals: the 15 locked manual pages come from one installation manual, and the model took 11 of them for data sheets. The 28 scanned pages without text are wrong for both methods.

## Limits

- Labels are per file: a cover page or an annex takes the type of its file in training.
- All the real packages come from one project, so a supplier can appear in training and in the test under different MAFs.
- A page without a text layer is `other` for both methods; neither reads scans yet.
